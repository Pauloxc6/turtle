Turtle ORM — MySQL

Documentação do driver MySQL para a biblioteca Turtle ORM em Bash.

GETTING STARTED

Quickstart

A biblioteca Turtle começa com um objeto Database, um Usuário e uma ou mais classe Model. O objeto Database gerencia o banco de dados, enquanto as funções Model são responsáveis pela definição das tabelas e seus campos. 

#!/usr/bin/env bash

source "orm"
source "dotenv"

db="shop"

ruser=$(dotenv:get "MYSQL_ROOT_USER")
rpass=$(dotenv:get "MYSQL_ROOT_PASS")

user=$(dotenv:get "MYSQL_USER")
pass=$(dotenv:get "MYSQL_PASS")

MysqlDatabase "${db}" "${user}" "${pass}" "${ruser}" "${rpass}"
  • Obs: Por motivos de segurança, é recomendável a utilização de um arquivo dotenv para armazenar as credenciais. Como nota pessoal, recomendo a utilização de outra biblioteca Dotenv.
Debug

Ativar o Debug

É possível ativar o modo debug na importação do framework, utilizando o argumento --debug:

source "orm" --debug
MODELS

Criação de tabelas

As tabelas são criadas utilizando MysqlDatabase:create.
Após a criação, BaseModel processa os Models e seus respectivos Fields.
Neste exemplo, será criado um pequeno esquema para uma loja, contendo clientes, produtos e pedidos. 

MysqlDatabase:create customers && BaseModel
MysqlDatabase:create products && BaseModel
MysqlDatabase:create orders && BaseModel
MODELS

Fields

Os campos são adicionados às tabelas através das funções Model:*Filed.
O primeiro argumento representa a tabela e o segundo representa o nome da coluna.
Os campos também podem receber propriedades adicionais, como unique e notnull.

TextField

Model:TextFiled cria uma coluna do tipo TEXT.

Model:TextFiled customers name && BaseModel
Model:TextFiled customers email unique && BaseModel
Model:TextFiled customers phone unique notnull && BaseModel

IntegerField

Model:IntegerFiled cria uma coluna do tipo INTEGER.

Model:IntegerFiled customers age && BaseModel
Model:IntegerFiled products stock notnull && BaseModel

FloatField

Model:FloatField cria uma coluna do tipo FLOAT.

Model:FloatField products price notnull && BaseModel

BlobField

Model:BlobFiled cria uma coluna do tipo BLOB.

Model:BlobFiled products image && BaseModel

BooleanField

Model:BooleanFiled cria uma coluna do tipo BOOLEAN.

Model:BooleanFiled products productActive 1 && BaseModel
  • Obs: Para difinir um dado tipo boolean utilizamos o 0 para FALSE e 1 para TRUE.

DatetimeField

Model:DatetimeFiled cria uma coluna do tipo DATETIME.

Model:DatetimeFiled products timestamp 'format=24' && BaseModel
  • Obs: A saida da data pode ser altarada para 24 horas ou 12 horas, especificando com format=24 ou format=12.
MODELS

A definição das tabelas pode ser combinada para representar uma estrutura mais próxima de uma aplicação real.

Foreign Keys

As chaves estrangeiras são definidas através de Model:ForeignKeyField.
Por padrão, as colunas id são configuradas como PRIMARY KEY. ForeignKeyField adiciona uma coluna que estabelece
uma referência entre duas tabelas. 

Model:ForeignKeyField orders customers
DATABASE

Insert

Os registros são inseridos utilizando MysqlDatabase:insert.
O primeiro argumento representa a tabela, o segundo representa a coluna e o terceiro representa o valor que será armazenado. 

MysqlDatabase:insert customers name "Paulo Santos"
MysqlDatabase:insert customers email "paulo@example.com"
DATABASE

Update

Os registros existentes podem ser atualizados utilizando MysqlDatabase:update.
O último argumento representa o ID do registro que será atualizado. 

MysqlDatabase:update customers name "Paulo Cezar Santos" 1
DATABASE

Select

Os registros de uma tabela podem ser consultados utilizando MysqlDatabase:select.

MysqlDatabase:select customers <json>
MysqlDatabase:select products <json>

A saida pode ser modifca através de <json> colocado no por último.

DATABASE

Get

Os registros de um tabela podem ser consultados através pelo id, utilizando: MysqlDatabase:get 

MysqlDatabase:get customers 1 <json>

A saida pode ser modifca através de <json> colocados no por último.

  • Obs: Por padrão o id é setado como 1 em caso de não expecificado.
DATABASE

Queries Customizadas

Consultas SQL personalizadas podem ser executadas utilizando MysqlDatabase:query.
A query pode ser passada diretamente para a função através de um Here Document.

Para consultas SQL diretas, utilize a sintaxe Heredoc:

MysqlDatabase:query <<SQL
SELECT 
    name, 
    email 
FROM 
    customers 
WHERE 
    id = 1;
SQL
  • Obs: A saida por padrão das queries customizadas é em formatada para <json>.
DATABASE

Delete

Um registro pode ser removido utilizando MysqlDatabase:delete.
O segundo argumento representa o ID do registro que será removido. 

MysqlDatabase:delete customers 1
SCHEMA

Schema

O schema de uma tabela pode ser exibido utilizando MysqlDatabase:check schema.

MysqlDatabase:check schema customers
  • Obs: A saida por padrão do check schema é em formatada para <json>.
SCHEMA

Indexes

Os índices associados a uma tabela podem ser consultados através de MysqlDatabase:check indexs.

MysqlDatabase:check indexs customers
MysqlDatabase:delete.index customers email
  • Obs: A saida por padrão do check indexs é em formatada para <json>.
SCHEMA

Table Info

As informações estruturais das colunas podem ser consultadas através de MysqlDatabase:check table-info.

MysqlDatabase:check table-info customers
  • Obs: A saída por padrão do check table-info é em formatada para <json>.
SCHEMA

Table Errors

As informações de erros das tabelas podem ser consultadas através de MysqlDatabase:check table-errors.

MysqlDatabase:check table-errors customers
  • Obs: A saída por padrão do check table-info é em formatada para <json>.
SCHEMA

Drop

Uma tabela pode ser removida utilizando MysqlDatabase:drop.

MysqlDatabase:drop "customers"

Um banco de dados pode ser removido utilizando MysqlDatabase:drop.database.

MysqlDatabase:drop.database "${db}"

Um usuário pode ser removido utilizando MysqlDatabase:drop.user.

MysqlDatabase:drop.user "${user}"
REFERENCE

API Reference

Módulo Função Descrição
MysqlDatabase create, insert, update, select, query, delete, readall, drop Gera comandos SQL e operações na base SQLite.
Model TextFiled, IntegerFiled, FloatField, BlobFiled, BooleanField, DatetimeField, ForeignKeyField Declara tipos de dados e relacionamentos.
BaseModel BaseModel Aplica as alterações declaradas no schema.
